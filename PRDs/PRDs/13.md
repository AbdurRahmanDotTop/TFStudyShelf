# 1. Product Objective

TFStudyShelf should evolve from a basic content-management system into a structured digital learning platform containing two major content domains:

**Content**

* Books
* Courses

Books and Courses must each contain their complete child content and management capabilities inside the parent entity itself.

The primary principle is:

> **Admin should open a Book or Course and manage everything belonging to that Book or Course without jumping between unrelated global CRUD screens.**

The frontend web application and mobile application must consume the same backend content model and render all supported media through their original URLs or storage references.



Example:

```json

  "provider": "cloudflare_stream",
  "url": "...",
  "thumbnail": "...",
  "duration": 320
}
```

The UI must not contain provider-specific logic everywhere.

* Books are managed entirely from Book Management.
* Chapters are managed inside Books.
* Questions are managed inside Books and reusable through question banks.
* Quizzes are managed from Books.
* Flashcards are managed from Books.
* Courses are available under Content.
* Courses contain a complete LMS management workspace.
* Media can be attached using URLs.
* External storage URLs load correctly.
* Admin can preview content.
* Admin can publish/unpublish content.

* Book content is fully readable online.
* Course content is fully readable online.
* Videos play without forcing PDF downloads.
* Audio plays correctly.
* Images load correctly.
* PDFs have an online viewer.
* Assessments function correctly.
* Progress is saved.
* Course navigation works.

### Mobile

* Same content appears through API.
* Media URLs resolve correctly.
* Course curriculum works.
* Progress works.
* Offline-capable content works according to access rules.

### Design

* Only `#212121`, `#FF7759`, `#FAFAFA` and gradients derived from them are used.
* Manrope is used for all standard UI/body/headings.
* Geist Mono is used for technical/data/code presentation.

### Engineering

* No duplicate implementation.
* No unnecessary duplicate APIs.
* No broken existing functionality.
* No dead routes knowingly left behind.
* No inconsistent Book/Course content models.
* No frontend hard-coded learning content.
* No provider-specific media logic scattered across components.
